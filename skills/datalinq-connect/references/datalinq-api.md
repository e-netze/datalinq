# DataLinq MCP server

The DataLinq instance hosts an MCP server (streamable HTTP, **stateful sessions**) at:

```
<datalinq-url>/datalinq-mcp
```

The server is registered only on **Test/Development** instances (`DataLinqEnvironmentType`). On Production the endpoint, agent tokens and preview tokens do not exist.

Sessions are stateful because the server sends approval requests (MCP elicitation) back to the client. Behind a load balancer use sticky sessions.

## Client configuration

DataLinq Code (*Settings* -> *MCP Agent Token*) generates the token and a ready-to-copy config. VS Code / GitHub Copilot (`.vscode/mcp.json`), token kept out of the file via an input variable:

```json
{
  "inputs": [
	{ "type": "promptString", "id": "datalinq-token", "description": "DataLinq MCP agent token", "password": true }
  ],
  "servers": {
	"datalinq": {
	  "type": "http",
	  "url": "https://<datalinq-url>/datalinq-mcp",
	  "headers": { "Authorization": "Bearer ${input:datalinq-token}" }
	}
  }
}
```

Claude Code: `claude mcp add --transport http datalinq https://<datalinq-url>/datalinq-mcp --header "Authorization: Bearer $DATALINQ_MCP_TOKEN"`

## Authentication (agent tokens, no passwords in the agent)

- Every request to `/datalinq-mcp` needs `Authorization: Bearer dla_<random>`. Other DataLinq cookies / `datalinq-token` headers are ignored on this route. Missing or invalid token -> `401` with `WWW-Authenticate: Bearer realm="datalinq-mcp"`.
- Tokens are generated by the signed-in user in DataLinq Code (*Settings* -> *MCP Agent Token*, API `DataLinqCodeApi/mcp/token`) with a name and a lifetime (8 h, 24 h, 3 days, 7 days; capped by `DataLinqMcpOptions.MaxAgentTokenLifetimeHours`, default 168). The token is shown **once**.
- The token carries the user's DataLinq Code identity and roles; the agent acts with exactly these permissions.
- The server stores only a SHA-256 hash (plus name, user, created, expires, last used) in an encrypted registry file (`DataLinqMcpOptions.AgentTokenRegistryPath`, default `<storage>/mcp-agent-tokens.blb`). Unreadable registry -> no token is valid.
- The same dialog lists the user's active tokens; **Revoke** invalidates a token immediately (also across instances sharing the storage).

## Authorization

Same rules as the DataLinq Code API: `datalinq-code` role and rights for the endpoint (role parameter or endpoint creator). `create_view` needs the create-view right, `create_query` the create-query right.

## Approval (server-side human in the loop)

Tools that run queries or change stored items call `DataLinqMcpApproval` on the server. It sends an MCP elicitation (`approve: boolean`, optional `remember: boolean`) that the client shows to the **user**.

| Result | Tool response |
|---|---|
| accepted + approve=true | executed |
| declined / cancelled / approve=false | error "The user did NOT approve ..." - nothing executed |
| client without elicitation capability | error "Action refused ... does not support approval dialogs" - nothing executed |

"Remember" (per session, max 8 h, per route and kind) is offered for `sample_query`, `get_preview_link`, `save_view`, `patch_view`, `patch_view_asset`. Never for `create_view`, `update_view`, `create_query`, `update_query`, `run_sql_preview`.

Compile checks run **before** the dialog, so the user is only asked about changes that compile. There are no delete tools.

## Preview links

The link token is single use and must be opened within `PreviewLinkLifetimeSeconds` (default 120 s). Opening it creates an HttpOnly session cookie (`PreviewSessionLifetimeSeconds`, default 600 s) that authenticates only this route (plus follow-up requests of the same endpoint) for the user who created it. Request a fresh link for the user at the end.
